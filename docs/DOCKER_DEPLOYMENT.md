# Docker Deployment Guide

## Why Docker is Needed for Render

**Problem**: Render's native Python environment does **not** include Chrome or ChromeDriver, which are required for the LCR scraping feature.

**Solution**: Use Docker to create a custom environment with everything installed.

## How Docker Works with Render

### Without Docker (Doesn't Work) ❌
```
Your Code → Render's Python Environment
                    ↓
              No Chrome installed
                    ↓
        Scraping feature fails!
```

### With Docker (Works!) ✅
```
Dockerfile → Builds custom image with:
              - Python 3.11
              - Google Chrome
              - ChromeDriver
              - All Python packages
                    ↓
         Render runs your custom container
                    ↓
         Scraping feature works!
```

## What the Dockerfile Does

The `Dockerfile` in your repository contains instructions to build a Linux container with everything needed:

### Step-by-Step Breakdown

```dockerfile
FROM python:3.11-slim
```
**Starts with**: Minimal Python 3.11 installation on Linux

```dockerfile
RUN apt-get update && apt-get install -y \
    wget gnupg unzip curl \
    fonts-liberation libasound2 ...
```
**Installs**: System libraries required by Chrome

```dockerfile
RUN wget ... google-chrome-stable
```
**Installs**: Google Chrome browser

```dockerfile
RUN ... chromedriver ...
```
**Installs**: ChromeDriver (matches Chrome version automatically)

```dockerfile
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
```
**Installs**: Your Python packages (Flask, Selenium, etc.)

```dockerfile
COPY . .
```
**Copies**: Your application code into the container

```dockerfile
CMD gunicorn --bind 0.0.0.0:${PORT:-8181} app:app
```
**Runs**: Your app with gunicorn (production server)

## How Render Detects Docker

When Render sees a `Dockerfile` in your repository root:
1. ✅ Automatically uses Docker build
2. ❌ Ignores `render.yaml` (no longer used)
3. ✅ Builds your custom image
4. ✅ Runs it as a container

**Note**: Environment variables, disk mounts, and domains still work the same!

## Deployment Process

### Step 1: Push to GitHub
```bash
git add Dockerfile
git commit -m "Add Docker support for Chrome/Selenium"
git push
```

### Step 2: Render Detects Dockerfile
- Render automatically switches from native Python to Docker
- Build time increases (5-10 minutes first time, then cached)
- Chrome/ChromeDriver are included in the image

### Step 3: Configure Render Settings

**Environment Variables** (set in Render dashboard):
- `SECRET_KEY`: (auto-generated by Render)
- `PORT`: (auto-provided by Render)

**Persistent Disk** (set in Render dashboard):
- Name: `sqlite-data`
- Mount Path: `/app/instance`
- Size: 1GB

This is the same as before - Docker doesn't change these settings!

### Step 4: Deploy
- Render builds the Docker image
- Deploys the container
- Your app runs with Chrome available! ✅

## Local Development vs Production

### Local (Windows)
- Uses `chromedriver-win64/chromedriver.exe` from repo
- No Docker needed
- Just run `python app.py`

### Production (Render/Linux)
- Uses Docker-installed ChromeDriver (Linux version)
- Automatically switches from `chromedriver.exe` to system ChromeDriver
- Your code handles both automatically!

## Testing the Docker Build Locally (Optional)

If you want to test the Docker build on your machine:

```bash
# Build the image
docker build -t ministering-interviews .

# Run the container
docker run -p 8181:8181 -e SECRET_KEY=test-key ministering-interviews

# Access at http://localhost:8181
```

**Note**: This creates a Linux container, so it won't use your Windows ChromeDriver.

## Troubleshooting

### Build Fails on Render
- Check Render logs for specific error
- Chrome version mismatch: Update ChromeDriver version in Dockerfile
- Timeout: Increase build timeout in Render settings

### Scraping Still Fails
- Check if headless mode is enabled (should be for production)
- Verify ChromeDriver and Chrome versions match
- Check Render logs for Selenium errors

### Disk Not Persisting
- Verify mount path is `/app/instance` in both:
  - Dockerfile: `RUN mkdir -p /app/instance`
  - Render dashboard: Disk mount path

## Why Not Use render.yaml?

`render.yaml` (Blueprint configuration) **cannot install Chrome/ChromeDriver** because:
- It only works with Render's native Python environment
- That environment doesn't include system packages like Chrome
- Chrome requires dozens of system libraries that can't be installed via Blueprint

**Docker solves this** by letting you install anything in a custom Linux image.

| Feature | Native Python (render.yaml) | Docker |
|---------|----------------------------|--------|
| **Chrome Support** | ❌ No | ✅ Yes |
| **Build Time** | Fast (2 min) | First: 5-10 min, Then: 2-3 min |
| **Caching** | Limited | ✅ Docker layers cached |
| **Flexibility** | Python only | ✅ Full system control |
| **Cost** | $1/month | $1/month (same!) |
| **Scraping Feature** | ❌ Broken | ✅ Works |

For this app, **Docker is required** because of Chrome/Selenium dependency.
